## The idea

Lee et al., "Deduplicating Training Data Makes Language Models Better" (ACL 2022, arXiv 2107.06499v2) reports how much near-duplicate (NEARDUP) and 50-token exact-duplicate (EXACTSUBSTR) text four corpora contain, and that T5-XL on deduplicated C4 emits ~10x less memorized text. The models are unreleased, but per-document NEARDUP cluster CSVs are public for C4, RealNews and Wiki-40B.

**The printed C4 numbers contradict each other, with no data needed:**
- Table 2 (paper.md L223) and §5.1 (L215): 3.04% of train examples have a near-duplicate in train, i.e. 11.09M of 364,868,892.
- Table 13 (L742): 364.87M → 350.48M examples, i.e. 14,383,892–14,393,892 removed (3.94%).
- A removed train doc has a duplicate in train (≤11.09M such docs) or only in validation (at most one per validation doc, 364,608). So removals ≤ 11.45M.

**Independent anchors agree with ~3.9%:** App. C steps 146K vs 152K (L556) and hours 126 vs 131 (L558); Table 6 days 5.26 vs 5.47; App. D "3.9% smaller" (L572); Fig. 1 (L189–199), whose 348,320,475 singletons leave 16,913,025 of the public train+valid 365,233,500 docs (4.63%) in multi-doc clusters, and whose 2,502,048 plotted clusters (a lower bound, edge sizes unplotted) cap keep-one-per-cluster removals at 14,410,977 (3.95%). Table 13 is supporting evidence only (H9).

**Beyond C4:** Wiki-40B's clusters show the same pattern (0.699% vs printed 0.39%); LM1B's Table 13 removal (426k–436k) sits below Fig. 8(a)'s floor of 515,809 (H5); the Google Research publication page prints a fifth C4 value, "1.68% of the C4 are near-duplicates". arXiv v1 and the ACL PDF match v2.

**Questions.** **Q1:** what do the authors' clusters say the C4 Table 2 cells should be, and which other corpus numbers (Table 13, Figs 1/8, §5.1 cluster facts, Table 11) reproduce? **Q2:** do the substring counts (§1's 61,036; Tables 9/10) reproduce? **Q3:** §6.3 (L354) says >5% of tokens in ~200k GPT-Neo 1.3B samples sit in 50-token Pile matches; Nasr et al. 2023 measure 0.160%. Which protocol choices make the ~30x gap?

## What makes it tractable (checked 2026-09-29; "re-checked" = 2026-09-30)

**CSV semantics** (re-checked on all of Wiki-40B and the first 114,604 C4 rows). Header `id,keep,cluster`; id = URL or `wikidata_id`; no split column. The README calls the middle column "deleted", but `keep` is 1 on every singleton and 0 on every multi-doc member (Wiki-40B: 3,228,888 vs 23,519), so the kept copy is unrecorded and removals are **rule-derived**. ## Step-0 hooks

- **H1.** Re-derive the C4 contradiction from printed numbers and public split sizes only.
- **H2. Random-split identity.** Table 2 column 3 equals the all-doc multi-cluster share (C4 4.60 vs 4.63, LM1B 4.92 vs 4.94, Wiki-40B 0.72 vs 0.72), and column 1 should sit near it: LM1B's 4.86 and the Wiki-40B CSV's 0.699 do; printed C4 3.04 and Wiki-40B 0.39 do not.
- **P1 (C4).** Rows = 365,233,500; Fig. 1 reproduces with edges dropped; train-with-dup ∈ [4.4, 4.8]%; rule-derived removals ∈ [14.38, 14.42]M. The two rules differ only by clusters holding both a train and a validation doc (≲17k if Table 2's 4.60% holds), near Table 13's 10k resolution; "remove every member" (≈348.0M left) is clearly separable.
- **P2 (Wiki-40B), graded:** train-with-dup ∈ [0.65, 0.85]% hit (0.699%); removals 17–18k missed (16,996 / 15,461; the band used figure-undercounted clusters and all docs, not train docs).
- **P3.** Compute the random-split expectation for validation-with-validation from exact cluster sizes *before* comparing to C4's printed 1.59%.
- **H4. Numerology; test, don't believe.** Fig. 1's lower-bin-edge doc count is 11,114,054 = 3.043% of train+valid; Wiki-40B's 2 × clusters is 0.388% (plotted) or 0.391% (real). No rule gives both; a stale table stays possible (the 1.68% page shows the headline moved).
- **H5. LM1B, printed-only (derived 2026-09-30).** Fig. 8(a) puts 1,510,889 docs in multi-doc clusters; plotted lower-edge docs are 1,505,410, so ≤547 edge-size clusters are missing, and keeping ≤1 train doc per cluster removes ≥ 1,510,889 − 306,688 − 688,392 = 515,809. Table 13 allows 426,028–436,028.
- **H6.** Confirm on C4 that only the edges-dropped convention reproduces the labels, as on Wiki-40B (edges low gives 430/173 there, edges high 391/202).
- **H7.** §1's "0.02% of the samples in each dataset": 61,036/364,868,892 and 61/364,608 are both 0.0167%.
- **H8. Stage 6 guesses (GPT-Neo only).** Unprompted top-k 50 without the filter ≥1% memorized tokens; the filter cuts that ≥3x; Wikipedia prompts ≤0.5%.
- **H9. Table 13 copy error.** EXACTSUBSTR examples repeat NEARDUP for C4 (350.48M) and RealNews (28.39M), but App. C (L556) gives C4-EXACTSUBSTR ≈365M examples and §5.1 (L241) says EXACTSUBSTR removes none outright (LM1B's 30.30M → 30.16M shows emptied docs can drop).
